# 工作流管理接口实现总结

## 概述

参考工作流API文档和应用接口的实现模式，为工作流管理模块创建了完整的接口实现，包括REST控制器、门面模式、查询服务、命令服务、DTO/VO类以及领域实体。

## 实现结构

### 1. 接口层 (interfaces/workflow)

#### WorkflowRest.java
- REST控制器，提供HTTP API接口
- 包含所有工作流管理相关的端点：
  - `POST /api/v1/workflows` - 创建工作流
  - `PATCH /api/v1/workflows/{id}` - 更新工作流
  - `PUT /api/v1/workflows/{id}/config` - 更新工作流配置
  - `DELETE /api/v1/workflows/{id}` - 删除工作流
  - `POST /api/v1/workflows/{id}/duplicate` - 复制工作流
  - `GET /api/v1/workflows/{id}` - 获取工作流详情
  - `GET /api/v1/workflows` - 获取工作流列表
  - `GET /api/v1/workflows/statistics` - 获取工作流统计
  - `POST /api/v1/workflows/{id}/execute` - 执行工作流
  - `POST /api/v1/workflows/{id}/stop` - 停止工作流执行
  - `GET /api/v1/workflows/execution-logs` - 获取执行日志
  - `GET /api/v1/workflows/executions/{executionId}` - 获取执行详情
  - `GET /api/v1/workflows/{id}/versions` - 获取工作流版本列表
  - `GET /api/v1/workflows/{id}/versions/{versionId}` - 获取特定版本
  - `POST /api/v1/workflows/{id}/versions/{versionId}/restore` - 恢复到特定版本
  - `PATCH /api/v1/workflows/{id}/toggle` - 启用/禁用工作流

#### WorkflowFacade.java & WorkflowFacadeImpl.java
- 门面模式实现，封装业务逻辑
- 提供统一的业务接口
- 处理DTO和领域对象之间的转换

#### DTO类
- `WorkflowCreateDto` - 创建工作流请求参数
- `WorkflowUpdateDto` - 更新工作流请求参数
- `WorkflowFindDto` - 查询工作流请求参数
- `WorkflowConfigUpdateDto` - 更新工作流配置请求参数
- `WorkflowExecuteDto` - 执行工作流请求参数
- `WorkflowStopDto` - 停止工作流执行请求参数
- `WorkflowToggleDto` - 启用/禁用工作流请求参数
- `ExecutionLogFindDto` - 查询执行日志请求参数
- `WorkflowDuplicateDto` - 复制工作流请求参数

#### VO类
- `WorkflowDetailVo` - 工作流详情响应
- `WorkflowListVo` - 工作流列表项响应
- `WorkflowStatisticsVo` - 工作流统计响应
- `ExecutionLogVo` - 执行日志响应
- `ExecutionDetailVo` - 执行详情响应
- `WorkflowVersionVo` - 工作流版本响应
- `WorkflowExecuteResultVo` - 工作流执行结果响应
- `WorkflowStopResultVo` - 工作流停止结果响应
- `WorkflowToggleResultVo` - 工作流状态切换结果响应
- `WorkflowRestoreResultVo` - 工作流版本恢复结果响应

### 2. 应用层 (application)

#### WorkflowQuery.java & WorkflowQueryImpl.java
- 查询服务接口和实现
- 提供各种查询方法：
  - 基础查询（按ID、名称等）
  - 状态查询（活跃、草稿、归档等）
  - 类型查询（单轮任务流、多轮对话流等）
  - 执行查询（运行中、失败、成功等）
  - 特殊查询（最近创建、最多调用、最高成功率等）

#### WorkflowCmd.java & WorkflowCmdImpl.java
- 命令服务接口和实现
- 使用BizTemplate模式，与ApplicationCmdImpl保持一致
- 提供各种操作命令：
  - 基础操作（创建、更新、删除）
  - 配置管理（更新配置、验证配置）
  - 执行控制（执行、停止、暂停、恢复、取消）
  - 版本管理（创建版本、恢复版本）
  - 状态管理（启用/禁用、归档/取消归档）
  - 统计更新（记录执行、更新统计）
  - 资源管理（备份、恢复、清理）
  - 验证检查（依赖检查、节点连接验证、循环依赖检查）

### 3. 领域层 (domain/workflow)

#### Workflow.java
- 工作流实体类
- 包含完整的工作流属性：
  - 基本信息（名称、描述、类型、状态等）
  - 配置信息（节点、连线、变量、触发器等）
  - 统计信息（执行次数、成功率、平均执行时间等）
  - 版本控制（版本号、版本历史等）
  - 执行控制（超时、重试、并发等）
  - 监控配置（监控、告警、日志等）
  - 安全配置（访问控制、权限等）
  - 资源限制（内存、CPU、存储等）
  - 归档备份（归档状态、备份配置等）
  - 性能指标（可靠性、性能、可维护性评分等）

#### 枚举类
- `WorkflowType` - 工作流类型（单轮任务流、多轮对话流、批量处理流等）
- `WorkflowStatus` - 工作流状态（草稿、活跃、运行中、暂停等）

#### WorkflowConfig.java
- 工作流配置类
- 包含节点、连线、变量、触发器、执行配置、监控配置、安全配置等

#### WorkflowRepo.java
- 工作流仓储接口
- 定义数据访问方法

### 4. 转换器 (assembler)

#### WorkflowAssembler.java
- 数据转换器
- 处理DTO和领域对象之间的转换
- 提供默认值设置和格式化功能

## 业务规则

### 1. 工作流状态流转
```
创建 → draft → active → running → completed
              ↓                     ↓
            archived              failed → 可重试
```

### 2. 执行规则
- 必须从开始节点开始
- 按照连线顺序执行
- 支持条件分支
- 支持并行执行
- 错误时可配置重试
- 超时自动终止

### 3. 节点类型
- **start**: 开始节点（必须）
- **end**: 结束节点（必须）
- **llm**: LLM处理节点
- **condition**: 条件判断节点
- **tool**: 工具调用节点
- **code**: 代码执行节点
- **template**: 模板节点
- **knowledge**: 知识库检索节点

### 4. 版本控制
- 每次保存自动创建新版本
- 版本号遵循语义化版本（Semantic Versioning）
- 支持查看历史版本
- 支持恢复到任意版本
- 恢复操作会创建新版本
