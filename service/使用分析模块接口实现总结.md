## 架构特点

### 1. 分层架构
严格遵循DDD分层架构:
- **领域层(Domain)**: 实体、仓储接口
- **应用层(Application)**: 查询服务(Query)、复杂业务逻辑
- **接口层(Interfaces)**: REST控制器、门面模式、DTO/VO

### 2. 业务逻辑封装
- 使用`BizTemplate`模式统一处理业务逻辑
- 复杂聚合查询封装在QueryImpl中
- 时间范围解析和粒度自动判断

### 3. 数据转换
- **DTO**: 接收客户端请求参数(AnalyticsQueryDto)
- **Entity**: 领域实体，与数据库映射
- **VO**: 返回给客户端的视图对象
- **Converter**: 静态转换器，负责Map到VO的转换

### 4. 持久化设计
- JPA实体映射，支持多租户
- 使用`TenantAuditingEntity`基类，自动处理审计字段
- Repository提供丰富的分组聚合查询

## 关键技术点

### 1. 时间范围处理
支持多种时间范围，自动解析：
```java
- "24hours": 最近24小时
- "7days": 最近7天(默认)
- "30days": 最近30天
- "90days": 最近90天
```

### 2. 数据粒度自动判断
根据时间范围自动选择合适的聚合粒度：
```java
- 24小时 → 按小时(hour)
- 7天/30天 → 按天(day)
- 90天 → 按周(week)
```

### 3. 聚合查询
使用Repository的分组查询方法：
```java
@Query("SELECT l.appId, COUNT(l), SUM(l.totalTokens), AVG(l.responseTimeMs) " +
    "FROM ApiUsageLog l WHERE l.requestTime BETWEEN :start AND :end " +
    "GROUP BY l.appId ORDER BY COUNT(l) DESC")
List<Object[]> groupByApp(@Param("start") LocalDateTime start, 
                          @Param("end") LocalDateTime end);
```

### 4. 百分位数计算
实现P50、P95、P99性能指标计算：
```java
private int calculatePercentile(List<Integer> sortedValues, int percentile) {
  int index = (int) Math.ceil(sortedValues.size() * percentile / 100.0) - 1;
  return sortedValues.get(Math.max(0, Math.min(index, sortedValues.size() - 1)));
}
```

### 5. 数据格式化
```java
- 数字格式化: "25,590" (千位分隔符)
- 大数简化: "1.2M" (百万), "5.3K" (千)
- 响应时间: "1.2s" 或 "350ms"
- 百分比: "+12.5%" (带符号和趋势)
```

### 6. Swagger文档
完整的API文档注解:
- `@Tag`: API分组("Analytics")
- `@Operation`: 操作描述
- `@Parameter`: 参数说明
- `@Schema`: 字段描述

## 业务规则

### 1. 时间范围
- 默认查询最近7天数据
- 支持应用ID筛选
- 自动计算上一周期数据用于对比

### 2. 数据聚合
- 按时间粒度分组(小时/天/周)
- 按应用、模型、接口等维度分组
- 自动计算百分比占比

### 3. 性能指标
- 平均响应时间(avgTime)
- P50: 中位数
- P95: 95%的请求响应时间
- P99: 99%的请求响应时间

### 4. 错误统计
- 按HTTP状态码分组
- 4xx客户端错误
- 5xx服务器错误
- 错误率计算: (失败数 / 总数) * 100

### 5. Top排名
- 默认Top 10
- 支持自定义limit参数
- 支持按调用次数、响应时间、成功率排序

### 核心表

```sql
- id: 主键

- model_id: 模型ID

- input_tokens: 输入Token数
- output_tokens: 输出Token数

- error_message: 错误信息
- ip_address: IP地址
- user_agent: 用户代理
- request_time: 请求时间
```

#### 2. usage_statistics - 使用统计聚合
```sql
- id: 主键
- stat_date: 统计日期
- granularity: 统计粒度(HOUR/DAY/WEEK/MONTH)
- app_id: 应用ID
- model_id: 模型ID
- total_calls: 总调用次数
- successful_calls: 成功调用次数
- failed_calls: 失败调用次数
- total_input_tokens: 总输入Token
- total_output_tokens: 总输出Token
- total_tokens: 总Token数
- total_cost: 总费用(分)
- avg_response_time_ms: 平均响应时间
- p50_response_time_ms: P50响应时间
- p95_response_time_ms: P95响应时间
- p99_response_time_ms: P99响应时间
```

### 字段特点
- 所有表继承多租户审计字段
- 时间字段使用LocalDateTime
- Token和费用使用整数存储(避免浮点精度问题)
- 枚举类型使用字符串存储

## 实现亮点

### 1. AnalyticsQueryImpl实现
- **职责**: 封装复杂的数据聚合查询逻辑
- **关键逻辑**:
  - 按时间粒度分组聚合(groupByGranularity)
  - 百分位数计算(P50/P95/P99)
  - 周期对比和变化百分比计算
  - 错误名称映射(HTTP状态码)
- **查询优化**: 使用Repository的原生分组查询，减少数据传输

### 2. AnalyticsConverter转换器
- **Map -> VO转换**: 7个核心转换方法
  - `toOverviewVo()`: 概览统计，包含4个核心指标
  - `toApiCallsTrendVo()`: API调用趋势，含汇总统计
  - `toTokenUsageTrendVo()`: Token使用趋势
  - `toAppDistributionVo()`: 应用分布
  - `toModelDistributionVo()`: 模型分布，自动分配颜色
  - `toTopEndpointsVo()`: Top接口
  - `toErrorAnalysisVo()`: 错误分析
- **数据格式化**: 数字千位分隔、大数简化、百分比、响应时间

### 3. AnalyticsFacadeImpl门面
- **职责**: 协调Query服务，处理时间范围和粒度
- **关键功能**:
  - 时间范围解析(parseTimeRange)
  - 粒度自动判断(determineGranularity)
  - DTO到时间参数的转换
  - 调用Converter进行数据转换

### 4. AnalyticsRest控制器
- **8个REST接口**: 对应8种分析功能
- **完整的Swagger文档**: 每个接口都有详细描述
- **参数验证**: 使用`@Valid`和`@ParameterObject`
- **统一响应格式**: 使用`ApiLocaleResult`包装

### 5. Repository聚合查询
- **按应用分组**: `groupByApp()` - 统计调用、Token、响应时间
- **按模型分组**: `groupByModel()` - 模型使用分布
- **按接口分组**: `groupByEndpoint()` - Top接口统计
- **按状态码分组**: `groupByStatusCode()` - 错误分析
- **性能统计**: COUNT、SUM、AVG等聚合函数
