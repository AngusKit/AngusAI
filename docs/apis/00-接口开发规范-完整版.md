## 1. 项目结构和模块划分

### 1.1 顶层模块结构

```
AngusAI/
├── service/
│   ├── api/          # 公共 API 层 —— 对外暴露的 DTO、VO、Remote 接口
│   ├── core/         # 核心业务层 —— DDD 四层架构实现
│   ├── boot/         # 启动模块 —— Spring Boot 主入口、配置
│   ├── conf/         # 配置文件
│   └── extension/    # 扩展插件（如短信、云服务）
├── web/              # 前端资源
├── assembly/         # 打包组装
└── docs/             # 规范文档
```

### 1.2 DDD 四层架构（core 模块）

```
service/core/src/main/java/cloud/xcan/angus/core/ai/
├── interfaces/                  # 接口层
│   └── {module}/
│       ├── {Module}Rest.java           # REST 控制器
│       └── facade/
│           ├── {Module}Facade.java     # 门面接口
│           ├── dto/                    # 数据传输对象
│           ├── vo/                     # 视图对象
│           └── internal/
│               ├── {Module}FacadeImpl.java   # 门面实现
│               └── assembler/
│                   └── {Module}Assembler.java
├── application/                 # 应用层
│   ├── cmd/{module}/
│   │   ├── {Module}Cmd.java            # 命令接口（写操作）
│   │   └── impl/{Module}CmdImpl.java
│   └── query/{module}/
│       ├── {Module}Query.java          # 查询接口（读操作）
│       └── impl/{Module}QueryImpl.java
├── domain/                      # 领域层
│   └── {module}/
│       ├── {Module}.java               # 领域实体
│       ├── {Module}Repo.java           # 仓储接口
│       └── enums/
└── infra/                       # 基础设施层
    └── persistence/
        ├── mysql/{module}/{Module}RepoMysql.java
        └── postgres/{module}/{Module}RepoPostgres.java
```

### 1.3 api 模块（公共接口）

```
service/api/src/main/java/cloud/xcan/angus/
├── api/commonlink/    # 跨模块公共实体、仓储接口
│   ├── user/User.java, UserRepo.java
│   ├── department/, group/, role/, quota/ ...
├── api/ai/            # 对外 Feign 远程接口
│   ├── user/UserRemote.java
│   └── email/EmailRemote.java
└── api/manager/       # 领域服务 Manager（跨模块调用）
    └── impl/
```

### 1.4 依赖规则

| 方向 | 允许 ✅ | 禁止 ❌ |
|------|--------|--------|
| 接口层 | → 应用层、领域层 | → 基础设施层 |
| 应用层 | → 领域层 | → 基础设施层、接口层 |
| 领域层 | 仅依赖自身 | → 任何其他层 |
| 基础设施层 | → 领域层（实现接口） | → 应用层、接口层 |

| 创建 DTO | `{Module}CreateDto` | `DepartmentCreateDto` |
| 更新 DTO | `{Module}UpdateDto` | `DepartmentUpdateDto` |
| 查询 DTO | `{Module}FindDto` | `DepartmentFindDto` |
| 详情 VO | `{Module}DetailVo` | `DepartmentDetailVo` |
| 列表 VO | `{Module}ListVo` | `DepartmentListVo` |

### 2.2 方法名规范

**REST 方法名（Controller 层）：**

| 操作 | 方法名 | 示例 |
|------|-------|------|
| 创建 | `create` | `create(dto)` |
| 完整更新 | `update` | `update(id, dto)` |
| 部分更新 | `patch` 或 `updateXxx` | `patch(id, dto)`, `updateStatus(id, dto)` |
| 删除单个 | `delete` | `delete(id)` |
| 批量删除 | `deleteBatch` | `deleteBatch(dto)` |
| 获取详情 | `getDetail` | `getDetail(id)` |
| 获取列表 | `list` | `list(dto)` |
| 获取统计 | `getStats` | `getStats()` |
| 获取树 | `getTree` | `getTree(...)` |

**Facade / Query / Cmd 方法名：**

| 操作 | 方法名 |
|------|-------|
| 创建 | `create` |
| 更新 | `update` |
| 删除 | `delete` |
| 查询单个（含校验） | `findByXxxAndCheck` / `getXxx` |
| 查询单个（不校验） | `findByXxx` |
| 查询列表 | `list` / `find` |
| 批量操作 | `batchXxx` |
| 统计 | `getStatistics` / `count` |

### 2.3 包名规范

- 全小写，多单词用 `.` 分隔
- 业务模块名为单数名词：`user`, `department`, `group`, `role`, `quota`
- 子包规范：`dto`, `vo`, `internal`, `assembler`, `enums`, `impl`

**✅ DO：使用 AngusInfra 提供的 `BizConstant` 常量**


## 3. 分层职责

### 3.1 接口层（Interfaces Layer）

**职责（DO）：**
- 接收和解析 HTTP 请求参数
- 触发 JSR-303 参数校验（`@Valid`）
- **只能调用门面层（Facade）方法**，不得直接调用 Cmd/Query 服务、Manager 或 Repository
- 包装统一响应（`ApiLocaleResult`）
- 提供 Swagger/OpenAPI 注解

**禁止（DON'T）：**
- ❌ 包含任何业务逻辑
- ❌ **直接调用应用层（Cmd / Query）、基础设施层（Repo）或任何 Manager**
- ❌ 直接操作领域对象
- ❌ 处理事务

**关键注解：**
```java
@Tag(name = "...")
@Validated
@RestController
@RequestMapping("/api/v1/{resources}")
```

### 3.2 Facade 层（接口层内部）

**职责（DO）：**
- 协调 Cmd/Query 服务完成业务用例
- 将 DTO 转换为领域对象（via Assembler）
- 将领域对象转换为 VO（via Assembler）
- 批量填充关联数据（避免 N+1）
- 使用 `@NameJoin` 注解自动填充关联名称
- 构建分页结果（`buildVoPageResult`）

**禁止（DON'T）：**
- ❌ **直接调用基础设施层（Repo 类），必须通过应用层（Cmd/Query）访问数据**
- ❌ 添加 `@Transactional`
- ❌ 包含核心业务规则
- ❌ 直接操作数据库（含 EntityManager）

> **规则：Facade 中调用的 Query 和 Cmd 方法，若从门面层发起，必须在对应的 Cmd/Query 方法中包含 `BizTemplate` 模板；若为非门面层调用（如内部 Manager 调用），则不需要。**

### 3.3 应用层（Application Layer）

**Cmd 服务职责（DO）：**
- 执行写操作（创建、更新、删除）
- 管理事务（`@Transactional(rollbackFor = Exception.class)`）
- 使用 `BizTemplate` 包装业务流程
- 参数校验（`checkParams()`）+ 业务处理（`process()`）
- 记录操作日志

**Query 服务职责（DO）：**
- 执行读操作（单个查询、列表查询、统计）
- 类级别标注 `@Transactional(readOnly = true)`
- 使用 `BizTemplate` 包装
- 批量填充关联数据（`setXxxUser` 等方法）
- 支持全文搜索（fullTextSearch 切换 SearchRepo）
- **特例：统计类方法（如 `getStatistics()`）可直接返回统计 VO（`XxxStatisticsVo`）**，此时 Query 接口可引用接口层 VO 包中的统计 VO 类型

**禁止（DON'T）：**
- ❌ Cmd 中执行纯查询（应在 Query 中）
- ❌ Query 中执行数据写入
- ❌ 绕过领域对象直接操作 SQL
- ❌ **在应用层（Cmd/Query）中使用普通 DTO（XxxCreateDto / XxxUpdateDto / XxxFindDto 等），仅统计 VO 特例除外**
- ❌ **在基础设施层（RepoMysql / RepoPostgres）中引用任何 DTO 或 VO**

> **DTO/VO 层级约束：**
> - DTO（CreateDto / UpdateDto / FindDto 等）和 VO（DetailVo / ListVo 等）**只能出现在接口层**（`interfaces/` 包下）
> - 统计 VO（`XxxStatisticsVo`、`XxxUsageVo`）作为特例，**允许在应用层 Query 接口中作为方法返回类型**（见 `QuotaQuery.getStatistics()` → `QuotaStatisticsVo`）
> - 领域层和基础设施层不得出现任何 DTO/VO 类

### 3.4 领域层（Domain Layer）

**职责（DO）：**
- 定义领域实体（含业务行为方法）
- 定义仓储接口（`XxxRepo extends BaseRepository`）
- 定义枚举类型
- 包含业务规则

**禁止（DON'T）：**
- ❌ 依赖其他层（保持纯净）
- ❌ 包含 HTTP/Spring 相关注解（除 JPA 外）
- ❌ 直接注入 Spring Bean

### 3.5 基础设施层（Infrastructure Layer）

**职责（DO）：**
- 实现领域层定义的仓储接口
- MySQL 实现：`{Module}RepoMysql extends {Module}Repo`
- PostgreSQL 实现：`{Module}RepoPostgres extends {Module}Repo`
- 使用 `@Repository("xxxRepo")` 注解（同名以支持数据库切换）

**禁止（DON'T）：**
- ❌ 包含业务逻辑
- ❌ 依赖应用层或接口层

## 4. RESTful URL 设计规则

### 4.1 基本规则

| 规则 | 正确 ✅ | 错误 ❌ |
|------|--------|--------|
| 使用复数名词 | `/api/v1/departments` | `/api/v1/department` |
| 版本号在路径中 | `/api/v1/users` | `/api/users` |
| 全小写加连字符 | `/api/v1/email-templates` | `/api/v1/emailTemplates` |
| 子资源用嵌套路径 | `/api/v1/departments/{id}/users` | `/api/v1/deptUsers?deptId=` |
| 不在 URL 中用动词 | `/api/v1/roles/{id}/permissions` | `/api/v1/roles/getPermissions/{id}` |
| 特定操作用路径后缀 | `/api/v1/email/{id}/retry` | `/api/v1/retryEmail/{id}` |

### 4.2 URL 模式

```
# 标准 CRUD
POST    /api/v1/{resources}                    # 创建
PUT     /api/v1/{resources}/{id}               # 完整更新
PATCH   /api/v1/{resources}/{id}/{sub-action}  # 部分更新 / 状态变更
DELETE  /api/v1/{resources}/{id}               # 删除
GET     /api/v1/{resources}/{id}               # 详情
GET     /api/v1/{resources}                    # 列表（分页）

# 子资源
GET     /api/v1/{resources}/{id}/{sub-resources}
POST    /api/v1/{resources}/{id}/{sub-resources}
DELETE  /api/v1/{resources}/{id}/{sub-resources}/{subId}

# 统计/聚合
GET     /api/v1/{resources}/stats
GET     /api/v1/{resources}/{id}/stats

# 特定操作（用 PATCH 或 POST）
PATCH   /api/v1/{resources}/{id}/status        # 状态变更
PATCH   /api/v1/{resources}/{id}/manager       # 设置负责人
POST    /api/v1/{resources}/{id}/retry         # 重试操作
```

### 4.3 内部 API（服务间调用）

```
# 内部 API 使用 /innerapi 前缀
POST   /innerapi/v1/{resources}
GET    /innerapi/v1/{resources}/{id}
```


## 5. HTTP 方法与操作的对应关系

### 5.1 标准对照表

| HTTP 方法 | 操作语义 | HTTP 状态码 | 返回值 | 幂等性 |
|-----------|---------|-----------|-------|-------|
| `POST` | 创建资源 | `201 Created` | 创建后的资源 VO | 否 |
| `PUT` | 完整替换（全字段更新） | `200 OK` | 更新后的资源 VO | 是 |
| `PATCH` | 部分更新（状态/字段） | `200 OK` | 更新后的资源 VO | 是 |
| `DELETE` | 删除资源 | `204 No Content` | 无 | 是 |
| `GET` | 查询（无副作用） | `200 OK` | 资源 VO / 分页结果 | 是 |

### 5.2 特殊操作的 HTTP 方法选择

| 操作 | 方法 | URL 示例 |
|------|------|---------|
| 状态变更（启用/禁用） | `PATCH` | `PATCH /api/v1/roles/{id}/status` |
| 设置负责人/管理者 | `PATCH` | `PATCH /api/v1/departments/{id}/manager` |
| 发送邮件（有副作用） | `POST` | `POST /api/v1/email/send` |
| 重试（触发动作） | `POST` | `POST /api/v1/email/{id}/retry` |
| 取消 | `POST` | `POST /api/v1/email/{id}/cancel` |
| 刷新（数据同步） | `POST` | `POST /api/v1/services/refresh` |
| 批量删除 | `DELETE` | `DELETE /api/v1/users` + 请求体 |
| 设置默认 | `PUT` | `PUT /api/v1/roles/{id}/default` |

### 5.3 代码示例

```java
// ✅ 正确：创建用 POST + 201
@ResponseStatus(HttpStatus.CREATED)
@PostMapping
public ApiLocaleResult<UserDetailVo> create(@Valid @RequestBody UserCreateDto dto) {
  return ApiLocaleResult.success(userFacade.create(dto));
}

// ✅ 正确：完整更新用 PUT + 200
@ResponseStatus(HttpStatus.OK)
@PutMapping("/{id}")
public ApiLocaleResult<UserDetailVo> update(@PathVariable Long id,
    @Valid @RequestBody UserUpdateDto dto) {
  return ApiLocaleResult.success(userFacade.update(id, dto));
}

// ✅ 正确：状态更新用 PATCH + 200
@ResponseStatus(HttpStatus.OK)
@PatchMapping("/{id}/status")
public ApiLocaleResult<DepartmentDetailVo> updateStatus(@PathVariable Long id,
    @Valid @RequestBody EnabledStatusUpdateDto dto) {
  return ApiLocaleResult.success(departmentFacade.updateStatus(id, dto));
}

// ✅ 正确：删除用 DELETE + 204，无返回值
@ResponseStatus(HttpStatus.NO_CONTENT)
@DeleteMapping("/{id}")
public void delete(@PathVariable Long id) {
  departmentFacade.delete(id);
}

// ✅ 正确：列表查询用 GET + 200，@ParameterObject
@ResponseStatus(HttpStatus.OK)
@GetMapping
public ApiLocaleResult<PageResult<DepartmentDetailVo>> list(
    @Valid @ParameterObject DepartmentFindDto dto) {
  return ApiLocaleResult.success(departmentFacade.list(dto));
}
```

## 6. 统一响应格式

### 6.1 响应包装类

所有接口使用 `cloud.xcan.angus.remote.ApiLocaleResult<T>` 作为响应包装类（基于 AngusInfra）。

```java
// ApiResult 基础结构（来自 AngusInfra）
public class ApiResult<T> {
  private String code;        // 成功："S"，失败：错误码（如 "B_PROTOCOL_001"）
  private String message;     // 本地化消息
  private T data;             // 业务数据（可为 null）
  private LocalDateTime datetime; // 响应时间戳
  private Map<String, Object> ext; // 扩展字段（如 eKey、traceId）
}
```

### 6.2 成功响应格式

```json
{
  "code": "S",
  "message": "操作成功",
  "data": {
    "id": 123,
    "name": "研发部",
    "status": "ENABLED"
  },
  "datetime": "2026-03-16T08:27:26"
}
```

### 6.3 分页响应格式

```json
{
  "code": "S",
  "message": "操作成功",
  "data": {
    "total": 100,
    "list": [
      { "id": 1, "name": "研发部" },
      { "id": 2, "name": "运营部" }
    ]
  },
  "datetime": "2026-03-16T08:27:26"
}
```

### 6.4 错误响应格式

```json
{
  "code": "B_PROTOCOL_001",
  "message": "资源「用户」[ID: 123] 不存在",
  "data": null,
  "datetime": "2026-03-16T08:27:26",
  "ext": {
    "eKey": "RESOURCE_NOT_FOUND"
  }
}
```

### 6.5 空响应（DELETE 204）

DELETE 操作返回 `void`，HTTP 状态码 204，无响应体。

### 6.6 Controller 中的构建方式

```java
// 成功（带数据）
return ApiLocaleResult.success(facade.doSomething());

// 成功（带自定义消息）
return ApiLocaleResult.success("操作成功", facade.doSomething());

// 成功（无数据）
return ApiLocaleResult.success();

// 分页（data 为 PageResult<T>）
return ApiLocaleResult.success(facade.list(dto));
```

```java
// 接口层 Assembler - DTO → 查询 Specification
public static GenericSpecification<Department> getSpecification(DepartmentFindDto dto) {
  Set<SearchCriteria> filters = new SearchCriteriaBuilder<>(dto)
      .rangeSearchFields("id", "createdDate", "modifiedDate") // 支持范围查询（如 id[0]=1&id[1]=100）
      .orderByFields("id", "createdDate", "modifiedDate", "name", "code") // 允许排序的字段白名单
      .matchSearchFields("name", "code", "description")       // 全文搜索匹配字段
      .build();
  return new GenericSpecification<>(filters);
}
```

### 7.4 业务校验（BizTemplate.checkParams()）

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Quota update(Quota quota) {
  return new BizTemplate<Quota>() {
    Quota existing;

    @Override
    protected void checkParams() {
      // 1. 查询资源是否存在
      existing = quotaQuery.findByCodeAndCheck(quota.getCode());
      // 2. 业务规则校验
      if (Boolean.TRUE.equals(existing.getIsLicenseControl())) {
        throw ProtocolException.of("配额「{0}」由许可控制，不允许修改",
            new Object[]{existing.getName()});
      }
      if (quota.getLimit() != null && quota.getLimit() < existing.getUsed()) {
        throw ProtocolException.of("配额限额不能小于当前已使用量「{0}」",
            new Object[]{existing.getUsed()});
      }
    }

    @Override
    protected Quota process() {
      existing.setLimit(quota.getLimit());
      return quotaRepo.save(existing);
    }
  }.execute();
}
```

**校验层级（由外到内）：**
1. **JSR-303**（Controller 层）：格式、非空、长度、范围
2. **业务校验**（BizTemplate.checkParams()）：资源存在性、业务规则一致性
3. **数据库约束**（最后保障）：唯一键、非空约束

## 10. 安全要求

### 10.1 认证机制

- 所有接口默认通过 **OAuth2 Bearer Token** 认证（由 AngusInfra Spring Security 统一配置）
- 内部接口（`/innerapi/**`）使用 `SCOPE_inner_api_trust` 授权

### 10.2 鉴权注解

```java
// 仅运营客户端可访问
@PreAuthorize("@PPS.isOpClient()")
@RestController
public class AuthenticationClientRest { ... }

// 内部服务间调用
@PreAuthorize("hasAuthority('SCOPE_inner_api_trust')")
@RestController
public class AuthenticationClientInnerRest { ... }

// 条件激活（仅 Cloud 版）
@Conditional(value = CloudServiceEditionCondition.class)
```

### 10.3 多租户隔离

- 所有实体继承 `TenantAuditingEntity`，自动隔离租户数据
- `BizTemplate` 默认开启多租户控制（`multiTenantCtrl = true`）
- 跨租户操作必须显式关闭并手动处理：

```java
// 跨租户查询（谨慎使用，必须手动过滤 tenantId）
return new BizTemplate<List<Quota>>(false) {
  @Override
  protected List<Quota> process() {
    return quotaRepo.findByTenantId(tenantId);
  }
}.execute();
```

### 10.4 SQL 注入防护

```java
// ✅ 正确：使用命名参数
@Query("SELECT e FROM Email e WHERE e.templateId = :templateId")
long countByTemplateId(@Param("templateId") Long templateId);

// ❌ 错误：字符串拼接（SQL 注入风险！）
// @Query("SELECT e FROM Email e WHERE e.templateId = " + templateId)
```

禁止在 JPQL/SQL 中拼接字符串，统一使用 JPA Specification 或 `@Param` 命名参数。

### 10.5 敏感数据脱敏

- 密码字段存储前必须加密，响应 VO 中不返回或返回掩码
- SMTP 密码、API Secret 等敏感信息在 VO 中处理：`@JsonIgnore` 或脱敏值
- 用户手机号、邮箱按业务需要在 VO 中脱敏

### 10.6 细粒度权限校验

## 13. 事务管理规则

### 13.1 事务注解位置

| Cmd 方法（写操作） | `@Transactional(rollbackFor = Exception.class)` | **必须加** |

```java
// ✅ Query 实现：类级别只读事务
```

## 15. 禁止事项清单

### 15.1 架构相关

| # | 禁止行为 | 原因 |
|---|---------|------|
| 1 | Controller（接口层）直接调用 Cmd/Query/Manager/Repository | 接口层只能调用门面层（Facade），不得越级 |
| 2 | Controller 包含业务逻辑 | 职责不单一 |
| 3 | Facade 层直接调用 Repository（基础设施层） | 门面层必须通过应用层（Cmd/Query）访问数据 |
| 4 | Facade 层加 `@Transactional` | 事务边界应在 Cmd 层 |
| 5 | 领域实体注入 Spring Bean | 污染领域模型 |
| 6 | 跨服务直接调用 Repository | 应通过 API/Remote 接口 |
| 7 | Query 类执行写操作 | 违反 CQRS 原则 |
| 8 | 在应用层（Cmd/Query）使用普通 DTO（CreateDto/UpdateDto/FindDto） | DTO 只属于接口层，统计 VO 特例除外 |
| 9 | 在基础设施层（RepoMysql/RepoPostgres）引用任何 DTO 或 VO | 基础设施层只依赖领域层 |

### 15.2 数据访问相关

| # | 禁止行为 | 替代方案 |
|---|---------|---------|
| 10 | 拼接 SQL 字符串 | JPA Specification 或命名参数 |
| 11 | 循环内查数据库（N+1） | 批量查询 + Map 组装 |
| 12 | 事务内执行远程 HTTP 调用 | 事务外调用，或异步/消息 |
| 13 | 使用 `@GeneratedValue` 自增主键 | `uidGenerator.getUID()`（Snowflake） |

### 15.3 安全相关

| # | 禁止行为 |
|---|---------|
| 14 | 日志打印密码、Token、密钥 |
| 15 | 响应体返回原始密码/Token |
| 16 | 硬编码 Token/Secret 到代码 |
| 17 | 未鉴权的批量操作接口 |

### 15.4 代码质量相关

| # | 禁止行为 | 替代方案 |
|---|---------|---------|
| 18 | 硬编码魔法数字（如 `@Size(max=100)`） | `BizConstant.MAX_NAME_LENGTH` |
| 19 | 忽略 `@Valid` 注解 | Controller 参数必须加 `@Valid` |
| 20 | 缺少 `@ResponseStatus` | 每个接口显式声明 HTTP 状态码 |
| 21 | DELETE 接口有返回值 | DELETE 返回 `void`，状态码 204 |
| 22 | 缺少 `@Operation`、`@ApiResponse` | 所有 public 接口必须有文档注解 |
| 23 | 使用 `@Autowired` 注入 | 使用 `@Resource`（JSR-250） |
| 24 | 捕获异常后静默吞没（空 catch） | 至少 `log.error`，必要时重新抛出 |
| 25 | Query DTO 不继承 `PageQuery` | 分页 DTO 必须继承 `PageQuery` |
| 26 | 未重写 `getDefaultOrderBy()` | `PageQuery` 子类必须重写 |

```java
@Slf4j
@Service
public class DepartmentCmdImpl extends CommCmd<Department, Long> implements DepartmentCmd {

  @Resource
  private DepartmentRepo departmentRepo;
  @Resource
  private DepartmentQuery departmentQuery;
  @Resource
  private UserOperationLogCmd userOperationLogCmd;

  @Override
  @Transactional(rollbackFor = Exception.class)
  public Department create(Department department) {
    return new BizTemplate<Department>() {
      @Override
      protected void checkParams() {
        if (departmentRepo.existsByCode(department.getCode())) {
          throw ProtocolException.of("部门编码「{0}」已存在",
              new Object[]{department.getCode()});
        }
      }

      @Override
      protected Department process() {
        department.setId(uidGenerator.getUID());
        Department saved = departmentRepo.save(department);
        userOperationLogCmd.logSuccessByMessageKey(
            OperationAction.CREATE, ResourceType.DEPARTMENT,
            saved.getId(), saved.getName(), "dept.created", null);
        return saved;
      }
    }.execute();
  }

  @Override
  protected BaseRepository<Department, Long> getRepository() {
    return departmentRepo;
  }
}
```

### 16.4 Query 实现样板

```java
@Service
@Transactional(readOnly = true)
public class DepartmentQueryImpl implements DepartmentQuery {

  @Resource
  private DepartmentRepo departmentRepo;
  @Resource
  private DepartmentSearchRepo departmentSearchRepo;
  @Resource
  private UserManager userManager;

  @Override
  public Department findByIdAndCheck(Long id) {
    return new BizTemplate<Department>() {
      @Override
      protected Department process() {
        return departmentRepo.findById(id)
            .orElseThrow(() -> ResourceNotFound.of(id, "Department"));
      }
    }.execute();
  }

  @Override
  public Page<Department> find(GenericSpecification<Department> spec, PageRequest pageable,
      boolean fullTextSearch, String[] match) {
    return new BizTemplate<Page<Department>>() {
      @Override
      protected Page<Department> process() {
        return fullTextSearch
            ? departmentSearchRepo.find(spec.getCriteria(), pageable, Department.class, match)
            : departmentRepo.findAll(spec, pageable);
      }
    }.execute();
  }

  @Override
  public void setLeaderUser(List<Department> departments) {
    Set<Long> leaderIds = departments.stream()
        .filter(d -> d.getLeaderId() != null)
        .map(Department::getLeaderId)
        .collect(Collectors.toSet());
    if (leaderIds.isEmpty()) return;
    Map<Long, UserBase> userMap = userManager.getUserBaseMap(leaderIds);
    departments.forEach(d -> {
      if (d.getLeaderId() != null) {
        UserBase leader = userMap.get(d.getLeaderId());
        if (leader != null) d.setLeaderName(leader.getFullName());
      }
    });
  }
}
```
